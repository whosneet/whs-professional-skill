# Contributing

Contributions are welcome. The skill is most useful when it reflects current
regulatory state and broad practitioner experience — anyone working in WHS /
OHS / EHS is invited to contribute.

## Types of contribution

**Highly welcome:**
- Regulatory updates (new amendments, new codes of practice, new penalty
  quanta, new commencement dates)
- Factual corrections to existing content
- Expansion of NZ-specific content
- New sections covering gaps identified in the README roadmap
- New worked examples in `references/output-templates.md`
- Glossary additions
- Clearer phrasing of existing content

**Welcome with discussion first:**
- Substantial structural changes
- New reference files
- Major reorganisations of existing files
- New sections in SKILL.md

**Not in scope:**
- Organisation-specific content in any file other than your own
  `company.md` (which you maintain locally)
- Content unrelated to WHS / OHS / EHS
- Commercial promotion of products or services
- Content infringing third-party intellectual property

## How to contribute

**For small fixes (typos, broken links, minor factual corrections):**
1. Fork the repository on GitHub
2. Edit the file directly in the GitHub web interface
3. Submit a pull request describing the change

**For larger contributions:**
1. Open an issue first describing what you want to add or change
2. Wait for discussion / acknowledgement
3. Fork the repository, make your changes on a branch
4. Submit a pull request linking back to the issue

## Style guidelines

- **Australian English** spelling throughout (organisation, recognise,
  programme → program, licence, behaviour)
- **Match the existing prose style** of the file you are editing —
  sentence rhythm, table conventions, heading depth, punctuation
- **No safety clichés** ("safety is everyone's responsibility", "stop think
  act") — direct, concrete language only
- **Concise**: aim for the shortest accurate phrasing
- **Cite sources** for regulatory claims: section numbers, code of practice
  references, dates
- **Attribute concepts** to named thinkers where applicable (see
  `frameworks.md` Section 12)
- **Maintain the two-layer architecture**: organisation-specific content
  goes in `company.md`; generic frameworks elsewhere

## Regulatory citations

When adding regulatory content, include:
- Jurisdiction (Cth, NSW, VIC, QLD, WA, SA, TAS, ACT, NT, NZ)
- Full Act/Regulation/Code name
- Section or clause reference
- Commencement date (for new provisions)
- Penalty quanta where relevant (with note that these are indexed)

## Pull request review

Pull requests are reviewed for:
- Accuracy (the content is correct and current)
- Scope (it fits the skill's purpose)
- Style (Australian English, concise, attributed)
- Architecture (it doesn't break the two-layer separation)

Reviewers may suggest edits. Substantive disagreements can be discussed in
the issue thread.

## Recognising contributors

Contributors are credited in the README's Acknowledgements section. Major
contributors may be added to a `CONTRIBUTORS.md` file.

## Code of conduct

Be civil and constructive. The WHS profession is small and reputational
damage is easy to do and hard to undo. Critique content, not contributors.
